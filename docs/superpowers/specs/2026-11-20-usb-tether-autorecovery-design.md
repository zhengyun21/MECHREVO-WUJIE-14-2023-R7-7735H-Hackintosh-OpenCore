# USB 网络共享自动恢复设计

## 目标

保留当前已经可用的 vivo iQOO Z8 USB 网络共享，并验证 macOS 在以下场景中
能够自动恢复上网：

- 手机已插入且开启 USB 网络共享；
- 重启并登录 macOS 后；
- 拔掉手机、等待数秒、重新插回后；
- 系统睡眠并唤醒后。

成功标准是：在上述场景中，macOS 能自动取得 IPv4 地址、DNS 和默认路由，
无需手工重新创建网络服务或反复开关手机共享。

## 已确认的现状

- 用户已经确认该手机能在当前 macOS 安装中通过 USB 共享网络。
- Windows 只读检查识别到 `vivo iQOO Z8`，USB VID/PID 为
  `2D95:600B`，并暴露 RNDIS 网络接口。
- 手机在当前物理连接中位于 AMD `161E` USB 控制器的 1 号端口。
- 按现有 ACPI 与 UTBMap 对照，对应 `XHC3` 的 `HS01`/`SS01` Type-C
  端口；这两个端口已经存在于 UTBMap 中。
- 当前 UTBMap 已将 USB-C 端口标记为 `UsbConnector=9`，无需重新生成映射。
- 当前 OpenCore 配置启用 `USBToolBox.kext` 与 `UTBMap.kext`。
- 当前 EFI 中没有额外的 HoRNDIS、NCM 或 Android RNDIS kext；现有系统
  已经具备让该手机共享网络所需的能力。

## 设计原则

1. 不修改 UTBMap、USBToolBox、XhciPortLimit 或任何 USB kext。
2. 不启用 AirportItlwm，不将 USB 网络修复与 AX210 Wi-Fi 恢复混在一起。
3. 优先使用 macOS 原生网络服务、DHCP 和自动连接能力。
4. 只有在物理验收证明原生行为不能恢复时，才增加一个范围受限的恢复任务。
5. 所有永久网络改动都要提供明确的回滚步骤，并保留修改前的只读快照。
6. 不按容易变化的 `en0`、`en1` 名称写死配置；通过网络服务名称和硬件端口
   识别 USB 网络接口。

## 实施阶段

### 阶段一：只读基线检查

在 macOS 中收集以下信息，不修改任何设置：

- 当前系统版本；
- 所有 USB 网络硬件端口与对应的网络服务名称；
- 该服务的 IPv4、DHCP、DNS、接口状态和默认路由；
- 当前网络服务顺序；
- 拔插手机前后的接口与路由变化。

基线检查必须确认 macOS 将该连接识别为一个独立的 USB Ethernet/RNDIS
服务，而不是把配置错误地写入 Wi-Fi 或其他有线接口。

### 阶段二：验证原生自动恢复

按以下顺序测试，每一步都在不修改 USBMap 的前提下进行：

1. 保持手机共享开启，确认可以解析域名并访问外部 IP。
2. 重启 macOS，登录后最多等待 60 秒，重复联网检查。
3. 拔掉手机 10 秒后重新插回，最多等待 60 秒，重复联网检查。
4. 如系统支持睡眠，睡眠后唤醒并重复联网检查。

如果所有场景都能自动恢复，则项目完成，不安装任何脚本或系统服务。

### 阶段三：条件性恢复任务

只有阶段二出现稳定复现的失败时才实施此阶段。

恢复任务只处理被识别为当前手机 USB 网络的服务，并遵守以下约束：

- 仅在该 USB 接口存在且链路已建立、但没有可用 IPv4 地址时采取动作；
- 使用 macOS 自带的 `networksetup`、`ipconfig`、`route` 和 `scutil`；
- 不在每个检查周期重复打印日志；
- 不修改防火墙、代理、Wi-Fi、AirportItlwm 或 UTBMap；
- 默认不强制把 USB 网络排在 Wi-Fi 之前；仅当没有其他可用默认路由时使用；
- 记录每次实际续租或接口重启动作及其结果；
- 提供单条命令停用并移除该任务的方法。

首轮实现优先采用低频状态检查，例如每 30 秒检查一次。只有在日志证明该方式
不足以覆盖拔插事件时，才考虑更复杂的 IOKit 事件监听。

## 失败处理

- 阶段一发现服务名或物理端口不匹配：停止修改，先重新确认当前端口与网络
  服务，不猜测 `enX` 编号。
- 原生测试出现“有 IP 地址但无默认路由”：只修复该 USB 服务的 DHCP 与路由，
  不重做整套网络配置。
- 原生测试出现接口反复上下线：回退恢复任务，保存系统日志，并优先检查 USB
  控制器稳定性，而不是继续叠加网络脚本。
- 任何测试导致其他 USB 设备异常：立即撤销网络层改动，并恢复修改前快照；
  不覆盖 UTBMap，因为本项目不应修改它。

## 回滚

阶段一和阶段二不需要回滚，因为只读取状态。

如果阶段三安装了恢复任务，回滚必须包含：

1. 卸载并停用对应的 launchd 任务；
2. 删除恢复脚本、日志配置和安装的 plist；
3. 恢复修改前的网络服务设置；
4. 重新确认 Wi-Fi、USB 网络、鼠标和存储设备均正常；
5. 确认 UTBMap 文件哈希与当前测试基线一致。

## 验收

最低验收条件：

- `ping` 外部 IP 成功；
- DNS 域名解析成功；
- 默认路由指向当前 USB 网络接口；
- 重启后可自动恢复；
- 拔插后可自动恢复；
- 鼠标、安装盘及其他既有 USB 设备不受影响；
- AirportItlwm 仍保持禁用；
- UTBMap 与 OpenCore USB 配置没有变化。
